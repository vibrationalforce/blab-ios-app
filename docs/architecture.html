Architecture

How Echoelmusic is built — one bio-reactive signal chain, from sensor to sound, on a lock-free real-time core. A precise reference for developers.

Developer reference · v10 · App coming soon

Echoelmusic is a native Apple app (Swift 6, strict concurrency). Modules never call each other directly — they produce and consume on a central bus, the EngineBus. Biology flows in as data, art flows out as audio, visuals and control. Built on AVFoundation, Accelerate/vDSP, Metal, CoreMIDI, CoreBluetooth and SwiftData, with a single external dependency (HaishinKit, for RTMP).

The Signal Chain

One chain runs the whole instrument. Sensors are fused into a normalized bio frame, published on the bus, and consumed in parallel by the synth voice, the OSC sender and the event detector. Performer input (MIDI/MPE) joins on its own topic and takes priority over bio for note gating.

SOURCES BUS (EngineBus) CONSUMERS Apple Watch / HealthKit ─┐ Polar H10 (BLE direct) ─┤ iPhone camera (rPPG) ─┼─▶ bioFrames ─┬─▶ BioReactiveSynthVoice ─▶ EchoelDDSP ─▶ AudioEngine ─▶ 🔊 Demo generator ─┘ (SPSC queue) ├─▶ OSCSender ─▶ UDP /echoelmusic/bio/* │ └─▶ BioEventPublisher ─▶ BioEventGraph ─┐ ▼ BioSourceManager (confidence fusion) │ bioEvents ◀───────────────────────────────────┘ CoreMIDI / MPE ──────────────▶ controllerEvents ─▶ synth notes (performer priority)

Three typed topics, three independent rates: bioFrames (≤4 Hz, the slow body signal), controllerEvents (real-time MIDI), bioEvents (discrete onsets). Each is a lock-free queue, so a slow sensor never stalls the audio thread.

EngineBus — the spine

EngineBus is @MainActor @Observable and is the single source of truth. It has a hybrid design: a control plane for SwiftUI (observable latestBio, latestControllerEvent, latestBioEvent snapshots) and a lock-free data plane of three typed queues for real-time consumers. Producers call nonisolated publish methods from any thread; consumers poll the queues without ever touching the bus object.

bioFrames
SPSCQueue<BioSampleFrame> — heart rate (BPM), HRV (normalized), breath rate, breath phase, coherence, motion energy.
controllerEvents
SPSCQueue<ControllerEvent> — note on/off, pitch bend, channel pressure, slide, air-CC (MIDI 2.0 / MPE-style).
bioEvents
SPSCQueue<BioEvent> — discrete onsets (heartbeat, breath inhale/exhale, motion peak) with a confidence score.
Publish API
publish(bio:), publish(controller:), publish(bioEvent:) — all nonisolated: atomic enqueue, then an async hop to the MainActor updates the observable snapshot. No locks, no allocation on the data plane.
SPSCQueue
Cache-line-padded, lock-free single-producer / single-consumer ring buffer. Power-of-two capacity; enqueue() drops the oldest on overflow; tryEnqueue(), dequeue(), peek(); counters for dropped/enqueued/dequeued. Index updates use atomic memory barriers — no malloc, no locks.

Bio Capture & Fusion

Several sources can feed the bus at once; BioSourceManager merges them into one BioSnapshot by confidence, so the highest-quality available signal wins.

Polar H10
PolarH10BioPublisher talks BLE directly (CoreBluetooth, no SDK) to the standard Heart Rate service (0x180D/0x2A37). It parses RR intervals (1/1024 s units) and emits one discrete .heartbeat event per beat; RMSSD is computed from a 30-interval window. Lowest latency — beats are timed, not derived from an averaged BPM.
Camera (rPPG)
CameraCapture + CameraAnalyzer — remote photoplethysmography (Verkruysse-style), 0.7–4 Hz bandpass, peak detection, RMSSD HRV and a BPM confidence score from the rear camera.
HealthKit
Apple Watch heart rate (~1 Hz). Note the platform constraint: watch HR carries 4–5 s latency, so it is not used for beat-accurate sync.
Fusion
BioSourceManager — confidence-weighted priority (Watch > camera rPPG > daily sources > demo fallback), with decay so a dropped source ages out gracefully.

Protected Bio-DSP Triad

Three pure value types form the read-only signal-conditioning core. They allocate nothing and take no locks, so they are safe to run on the audio thread. Contracts are pinned as SKILL.md specs and treated as protected (changed only with explicit approval).

BioSignalDeconvolver
struct — first conditioning stage: detrend (biquad high-pass; 0.5 Hz PPG/ECG, 1 Hz EEG, 0.1 Hz accelerometer) + mains notch (50/60 Hz, Q=30) + validity flag (recovering / valid / corrupt). Direct-Form-II-Transposed biquads. process(_:) → CleanedSample. Separates slow drift, mains hum and dropouts from the live signal.
HilbertSensorMapper
enum (static) — maps a 1-D sensor index to a 2-D grid coordinate along a Hilbert curve, so numerically adjacent channels land in spatially adjacent cells (Manhattan distance ≤ 1). map(index:order:), mapToGrid(values:gridSize:). Used to lay electrode/coherence arrays into 2-D textures without scrambling locality.
BioEventGraph
struct — turns continuous frames into discrete events. Heartbeat (adaptive threshold + 300 ms refractory + 2 s envelope follower, ≤200 bpm), breath phase markers (inhale on the 0.5 crossing, exhale on wrap), motion peak (hysteresis 0.6/0.3). process(…) → [BioEvent]; each event carries kind, confidence and an aux value (e.g. inter-beat interval). EEG-burst and coherence-shift detectors are reserved.

These modules use solid, well-understood DSP (RBJ-cookbook biquads, envelope/threshold and hysteresis detection); the design is informed by the bio-signal deconvolution and event-graph literature rather than porting any single paper verbatim.

Synthesis Engines

All synthesis is Accelerate/vDSP-vectorized and audio-thread-safe (pre-allocated buffers, @unchecked Sendable, no allocation in the render path). Each engine exposes the same bio-reactive mapping surface.

EchoelDDSP
Harmonic-plus-noise synthesizer — 64 sinusoidal partials (vvsinf/vDSP_dotpr), 65-band FIR noise, spectral morphing, timbre transfer, convolution reverb and isochronic entrainment. Carries the 7 core bio-mappings.
EchoelCellular
Cellular-automata synthesis — Wolfram rules 30/90/110/184 (256-cell 1-D) or 64×64 Game of Life (2-D), in wavetable, additive, FM and spectral modes.
EchoelModalBank
Physical modal resonator — up to 64 modes for bells, plates, strings, glass and drums; stiffness (inharmonicity), damping, size and brightness, with material morphing.
Toolkit
EchoelVDSPKit (FFT/DFT, convolution, biquad cascade, windowing), EchoelLFO, EchoelSVFilter (Chamberlin state-variable), EchoelEntrainment (Delta–Gamma isochronic) — shared building blocks.
Bio-mappings
Coherence → harmonicity; HRV → brightness/reverb; heart rate → vibrato/pulse; breath phase → amplitude envelope; breath depth → noise; LF/HF → spectral tilt; coherence trend → shape morph. Applied via synth.applyBioReactive(…).

Audio Foundation

AudioEngine
Master AVAudioEngine with a stereo mixer bus at 48 kHz. Hosts the synth source node, sampler voices and the mix/export chain.
AudioConfiguration
48 kHz preferred; buffer presets 128 / 256 / 512 frames (2.67 / 5.3 / 10.7 ms); playAndRecord session with Bluetooth; real-time thread priority.
Capture & mix
MicrophoneManager (1024-pt FFT analysis), RetroCapture (pre-roll ring buffer), AutoMixChain (EQ → compressor → limiter → LUFS), SingleExport (LUFS-normalized WAV/AAC).

Sequencer & Sampler

PatternEngine
8 tracks × 16 steps, 30–300 BPM, 16th-note clock (step = (60/BPM)/4 s).
SamplerVoice
One-shot WAV playback on an AVAudioSourceNode, fired lock-free via an atomic trigger counter (no allocation on the audio thread). BeatPlayer manages eight voices.

Studio UI

EchoelmusicApp (@main) configures audio before the UI, starts the bio publishers, and mounts StudioRoot. The root is a live BioStripView over a four-tab TabView. SwiftUI observes the EngineBus snapshots; nothing in the view layer touches the audio thread.

BioStripView
Always-on readout: HR · HRV · Br · Coh, applied synth-frame count, and activity dots (bio events, MIDI, OSC), plus a play/stop toggle and the active source tag.
Tabs
Tools (BeatTab — drum pads + step grid, implemented) · Works · Sync · Well (placeholders pending spec).

EchoelSync — OSC API

OSCSender mirrors the bio frame out over UDP (Network.framework), so any visual or audio tool on the network can react to the body. OSC 1.0, big-endian 32-bit floats, ~100 ms cadence (sent only when the frame changes). Default target localhost:8000; target latency <5 ms on LAN. Works with Resolume, TouchDesigner, MadMapper, Sonic Pi and TidalCycles.

Concurrency & Audio-Thread Safety

The split is strict. The control plane (@MainActor @Observable) drives SwiftUI; the data plane (lock-free SPSC queues) drives audio. A producer never blocks a consumer.

Forbidden on the audio thread

  • malloc / free, array growth
  • locks, mutexes, semaphores
  • ObjC messaging, GCD / async
  • file or network I/O, logging

Allowed

  • pre-allocated Float buffers
  • vDSP / Accelerate, C math
  • ring-buffer read/write
  • atomic-width property reads

Performer priority: when a MIDI note is held, controller input overrides the breath-gated envelope — the player always wins over the body.
