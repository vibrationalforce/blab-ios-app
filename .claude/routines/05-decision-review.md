## Your job

Check `decisions.csv` for decisions with `review_date` ≤ today.
Open a GitHub issue for each overdue decision so Michael reviews it.
One issue per overdue decision. Never open duplicates.

### Step-by-step

1. **Read decisions.csv:**
   ```bash
   gh api repos/vibrationalforce/Echoelmusic/contents/decisions.csv \
     --jq '.content' | base64 --decode
   ```

2. **Parse for overdue decisions — with a QUOTE-AWARE parser, never a comma split:**
   ```bash
   python3 -c '
   import csv, sys, datetime
   rows = list(csv.reader(open("decisions.csv", newline="", encoding="utf-8")))
   body = rows[1:]
   today = datetime.date.today().isoformat()
   SKIP = {"REVIEW_DUE", "REVIEWED"}          # the ONE due-predicate — see review.sh
   for r in body:
       if len(r) == 6 and r[4] <= today and r[5] not in SKIP:
           print(r[0], "|", r[4], "|", r[5], "|", r[1][:80])
   '
   ```
   - Format: `date,decision,reasoning,expected_outcome,review_date,status`
   - Fields contain commas and embedded quotes. Splitting on `,` puts a fragment of
     the *reasoning* into `review_date`. Measured 2026-08-08: that misread **241 of
     363** rows (#509).
   - Today's date: use `date +%Y-%m-%d` (UTC)

   > ⛔ Corrected 2026-08-08 (#510). This step used to say *"a decision is overdue when
   > `review_date` ≤ today AND `status` ≠ `CLOSED`"*. Measured over all 364 rows:
   > **`CLOSED` occurs zero times.** The log uses 22 different status tokens
   > (`active` 141, `ACTIVE` 130, `shipped` 42, `superseded…`, `RESOLVED`, `parked`, …)
   > and none of them is `CLOSED` — so that clause filtered **nothing**, and a
   > `shipped` or `superseded` decision would have been raised as an open question.
   > `review.sh` is the one definition; its predicate is copied above verbatim
   > (#416: one decision, one place). Widening it to also skip terminal statuses is a
   > judgment call about the review workflow, not a parse fix — 18 of today's 132 due
   > rows carry one.

3. **Check for existing open issues (avoid duplicates):**
   ```bash
   gh issue list --repo vibrationalforce/Echoelmusic \
     --label "decision-review" --state open --json number,title
   ```
   If an issue already exists with the decision text in the title, skip it.

4. **Open one issue per overdue decision:**
   ```bash
   gh issue create --repo vibrationalforce/Echoelmusic \
     --title "Decision Review: <decision short title>" \
     --label "decision-review" \
     --body "..."
   ```

### Issue body template

```markdown
## Decision Review Due

**Original decision:** <decision text>
**Date decided:** <date>
**Review due:** <review_date>

**Reasoning at the time:**
<reasoning>

**Expected outcome:**
<expected_outcome>

---

### Questions to answer in this review

1. Is this decision still valid?
2. Did the expected outcome occur?
3. Has anything changed that would reverse this decision?
4. Should the review date be extended?

**Actions:**
- Close this issue if decision is confirmed valid
- Extend `review_date` by 30 days if still being validated
- If reversed: append a NEW row recording the reversal and set the old row's status
  to `superseded` — do not overwrite the original reasoning, the log is a history

> ⛔ This block used to say *"update `decisions.csv` status to `CLOSED`"*. Nothing
> reads `CLOSED`, and nothing wrote it either (0 of 364 rows) — it would have been a
> 23rd status token invisible to `review.sh`. The tokens that already exist and mean
> "stop asking" are `superseded`, `shipped` and `RESOLVED`.

---
*Auto-generated by Decision Review Routine. See `decisions.csv` for full log.*
```
