SECTION 2 — TEMPO INVARIANT: FINAL RULING (RATIFIED)
================================================================================
CONFLICT: BioComposer.tempo(for:) case .flowFree implements
  pulled = hr * (1 - calm) + resonancePulseBPM * calm      (~L417)
i.e. tempo follows the pulse, converging to 72 BPM as coherence rises. This is
shipped and device-approved (decisions.csv 2026-06-22 "Klang ist erstmal gut",
refined 2026-07-03/2026-07-04 for glide). BIOSIGNAL_DOCTRINE meanwhile forbids
HR->tempo outright. Both cannot be invariants. An invariant the shipped product
violates is not an invariant — it is a trap for every future agent session.

RULING: KEEP THE FLOW SERVO. Make the invariant precise instead of absolute.
The doctrine's intent was to forbid the naive "your heartbeat IS the beat"
mapping (raw pulse driving the clock 1:1, jittering with every artifact). The
shipped design is a coherence-gated, glide-smoothed, clamped entrainment servo
that converges AWAY from the pulse as self-regulation improves. That is
defensible under the science-only doctrine and it is what the founder approved
with his ears.

NEW WORDING (into BIOSIGNAL_DOCTRINE + CLAUDE.md):
T1 — Tempo sources are enumerable and logged. Transport tempo may be set only
by (a) user lock/edit/tap, (b) the Flow entrainment servo, (c) automation
lanes. Every transport-play and every clock-reaching path logs tempoSource=
(user | flowServo | automation).
T2 — Raw heart rate never sets tempo directly. No path may assign any BPM
estimate (rPPG, BLE, HealthKit) to the clock without passing through the servo
(coherence blend + clamp 40-160 + glide) or an explicit user gesture.
studioLocked must be provably independent of heartRateBPM.
T3 — CI-enforced, not document-enforced. The tests are the invariant. Prose
that contradicts a green test is stale prose.

C9 — VISUALS BRIEF (design doc first, no code)
Approved in principle:
 - Kaleidoscope: a symmetry operator over the existing field output, not a new
   renderer. n-fold mirroring multiplies apparent flicker — apply FlashGuard
   AFTER the operator, never before.
 - Julia set (NOT Mandelbrot): c parameter driven by coherence and breath phase.
   A Mandelbrot zoom has no bio coupling and would be decoration; a Julia set
   the body reshapes is an instrument. Same aesthetic, honest mechanism.
 - "Mirror" look: camera silhouette/motion reflected into the field. This is the
   buildable, claim-free version of the "mirror neuron" idea. THE TERM "MIRROR
   NEURON" MUST NOT APPEAR in code, UI or docs — human mirror-neuron evidence is
   thin and popularly overstated; naming a visual after it is exactly the claim
   class the anti-esoterik doctrine forbids.
 - Water: a Look already exists. True fluid simulation is possible but must ship
   with a MEASURED thermal/GPU budget: rPPG runs camera AND torch, and thermal
   throttling degrades bio sampling before it degrades the visual.
Cross-cutting invariants for ALL looks (this is what "health, no claim" means):
 1. FlashGuard clamp applied to the FINAL composited frame.
 2. Luminance ramps, no hard cuts; honour Reduce Motion and Reduce Transparency.
 3. Deterministic seed per look so an exported loop reproduces its visual.
 4. Per-look performance budget: frame time + sustained thermal state with the
    camera active. A look that starves the bio pipeline is rejected regardless
    of beauty.
 5. Colour language stays the shipped CIE-1931 tone->light mapping. No
    wavelength-to-emotion and no wavelength-to-health claims anywhere.
 6. Every look reads the SAME BioSampleFrame the OSC senders publish, so an
    external Resolume patch and the in-app look respond identically.
NOT RECOMMENDED: a separate "health visuals" mode. Safety and evidence
discipline are properties of EVERY look; a labelled compartment implies the
others are unsafe and implies a health claim by contrast.

REAL FINDING IN THE SAME FUNCTION — `.studioLocked` DOES NOT RETURN THE LOCKED
TEMPO UNCONDITIONALLY. It returns `min(max(input.lockedTempo,
r.lowerBound), r.upperBound)` where `r = input.style.tempoRange`. So the
handover's `studioLockedIgnoresHeartRate` case, which expects `t == 124`,
passes only if the style under test has a tempo range containing 124 — it is
asserting the STYLE's window, not the invariant its own name states. The guard
therefore asserts what T2 actually says: for every heart rate the result is
IDENTICAL (and equals the style-clamped locked tempo). That version is true
under any style and goes red for exactly the reason it names.
