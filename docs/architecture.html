Architecture

How Echoelmusic is built — one bio-reactive signal chain, from sensor to sound, on a lock-free real-time core. A precise reference for developers, audited against the source.

Developer reference · v10 · App coming soon

Echoelmusic is a native Apple app (Swift 6, strict concurrency). Modules never call each other directly — they produce and consume on a central bus, the EngineBus. Biology flows in as data; art flows out as audio, visuals and control. Built on AVFoundation, Accelerate/vDSP, Metal, CoreMIDI, CoreBluetooth, HealthKit and SwiftData, with a single planned external dependency (HaishinKit, for RTMP). Every claim below is marked LIVE (shipping) or ROADMAP (designed, not yet built).

The Signal Chain

One chain runs the whole instrument. Sensors are fused into a normalized bio frame, published on the bus, and consumed in parallel by the synth voice, the OSC sender and the event detector. Performer input (MIDI/MPE) joins on its own topic and takes priority over bio for note gating.

SOURCES BUS (EngineBus) CONSUMERS HealthKit / Apple Watch ─┐ confidence fusion BLE Heart Rate (direct) ─┤ into one snapshot iPhone camera (rPPG) ─┼─▶ latestBio ─┬─▶ BioReactiveSynthVoice ─▶ EchoelDDSP ─▶ AudioEngine ─▶ OUT Demo (DEBUG) ─┘ (@MainActor, ~10 Hz) ├─▶ OSCSender ─▶ UDP /echoelmusic/bio/* └─▶ BioEventPublisher ─▶ BioEventGraph ─┐ bioEvents (SPSC) ◀──────────────────────────────┘ CoreMIDI 2.0 / MPE ───────────▶ controllerEvents (SPSC) ─▶ synth notes (performer priority)

The slow body signal flows over the @MainActor latestBio snapshot, polled at ~10 Hz — so a slow sensor never stalls the audio thread. The lock-free SPSC queues carry the real-time streams: controllerEvents (MIDI/MPE) and bioEvents (discrete onsets). A bioFrames queue is defined for a future full-rate path but is currently reserved and undrained.

Modulation, not control: bio signals are modulation sources for the parameter lanes you paint — not hard controllers. Tempo can optionally follow heart rate, but watch-HR latency (4–5 s) makes that a loose adopt, never a beat-lock. The expressivity lives in continuous modulation of your own automation.

EngineBus — the spine LIVE

EngineBus is @MainActor @Observable and is the single source of truth. It has a hybrid design: a control plane for SwiftUI (observable latestBio, latestControllerEvent, latestBioEvent snapshots) and a lock-free data plane of three typed queues for real-time consumers. Producers call nonisolated publish methods from any thread; consumers poll the queues without ever touching the bus object.

bioFrames
SPSCQueue<BioSampleFrame> — heart rate (BPM), HRV (normalized), breath rate, breath phase, coherence, motion energy.
controllerEvents
SPSCQueue<ControllerEvent> — note on/off, pitch bend, slide, air-CC (MPE).
bioEvents
SPSCQueue<BioEvent> — discrete onsets (heartbeat, breath inhale/exhale, motion peak) with a confidence score.
Publish API
publish(bio:), publish(controller:), publish(bioEvent:) — all nonisolated: atomic enqueue, then an async hop to the MainActor updates the observable snapshot. No locks, no allocation on the data plane.
SPSCQueue
Cache-line-padded, lock-free single-producer / single-consumer ring buffer. Power-of-two capacity; enqueue() drops the oldest on overflow; tryEnqueue(), dequeue(), peek(); counters for dropped/enqueued/dequeued. Index updates use atomic memory barriers — no malloc, no locks.

Multidimensional Control — MPE LIVE

Performer gestures arrive over CoreMIDI with the MIDI 2.0 protocol (MIDIInputPortCreateWithProtocol(._2_0)), parsing both MIDI 1.0 (16-bit) and MIDI 2.0 (32-bit) words and normalizing everything to clean float ranges. Each axis becomes a ControllerEvent on the bus — this is the multidimensional (MPE) layer: one note carries several continuous, independent dimensions of expression.

Note + velocity
.noteOn / .noteOff — note 0–127, velocity [0–1] (7-bit MIDI 1.0 or 16-bit MIDI 2.0).
Per-note pitch bend
.pitchBend — [−1…+1]; 14-bit (MIDI 1.0) or 32-bit (MIDI 2.0). The X / glide dimension.
Slide / timbre (CC 74)
.slide — [0–1]. The Y / vertical dimension on MPE controllers.
Air-CC (CC 21–31)
.airCC — [0–1], CC number preserved in auxCC. Breath / wind-controller and gestural "air" dimensions.
Next
.channelPressure (Z / pressure) and MPE member/master zone detection (RPN 6,6) are defined in the event model and wired in the next cycle. ROADMAP

Performer priority: while a MIDI note is held, controller input overrides the breath-gated bio envelope — the player always wins over the body.

Bio Capture & Fusion LIVE

Several sources can feed the bus at once; they are fused into one bio snapshot by confidence on the EngineBus latestBio path, so the highest-quality available signal wins.

HealthKit
EchoelBioEngine derives heart rate, RMSSD-normalized HRV, breath rate (iOS 17+) and coherence; HealthKitBioPublisher polls it every 500 ms and publishes a frame. This is the catch-all for Apple Watch and any device that writes to Apple Health — including the Oura Ring (any gen, incl. Ring 4) via Oura's Health sync. Watch HR carries 4–5 s latency and ring data is delayed/aggregated, so neither is used for beat-accurate sync — for that, use a BLE strap or the camera.
BLE Heart Rate
PolarH10BioPublisher connects over BLE (CoreBluetooth, no SDK) to any device exposing the standard Heart Rate service (0x180D/0x2A37) — Polar, Wahoo, Garmin/CooSpo/Magene straps, watches in HR-broadcast mode. Parses RR intervals (1/1024 s), emits one discrete .heartbeat per beat, computes RMSSD over a 30-interval window. Lowest latency — beats are timed, not averaged. (The Oura Ring exposes no real-time BLE to third parties, so it arrives via Apple Health instead.)
Camera (rPPG)
CameraCapture + CameraAnalyzer — finger-on-lens photoplethysmography: red-channel extraction, 0.7–4 Hz 2nd-order Butterworth bandpass (42–240 BPM), peak detection with IQR outlier rejection, RMSSD and a confidence score.
Fusion / Demo
Snapshot-level confidence priority (Watch > camera > daily > fallback) with decay, resolved on the latestBio path. BioSimulator provides a walking demo signal in DEBUG builds only and defers the moment a real source appears.

Protected Bio-DSP Triad LIVE

Three pure value types form the read-only signal-conditioning core. They allocate nothing and take no locks, so they are safe to run on the audio thread. Contracts are pinned as SKILL.md specs and treated as protected (changed only with explicit approval).

BioSignalDeconvolver
struct — first conditioning stage: detrend (biquad high-pass; 0.5 Hz PPG/ECG, 1 Hz EEG, 0.1 Hz accelerometer) + mains notch (50/60 Hz, Q=30) + validity flag (recovering / valid / corrupt). Direct-Form-II-Transposed biquads. process(_:) → CleanedSample.
HilbertSensorMapper
enum (static) — maps a 1-D sensor index to a 2-D grid coordinate along a Hilbert curve, so numerically adjacent channels land in spatially adjacent cells (Manhattan distance ≤ 1). map(index:order:), mapToGrid(values:gridSize:).
BioEventGraph
struct — continuous frames → discrete events. Heartbeat (adaptive threshold + 300 ms refractory + 2 s envelope, ≤200 bpm), breath phase markers (inhale on the 0.5 crossing, exhale on wrap), motion peak (hysteresis 0.6/0.3). Each BioEvent carries kind, confidence, aux (e.g. inter-beat interval). EEG-burst & coherence-shift detectors are reserved.

These modules use solid, well-understood DSP (RBJ-cookbook biquads, envelope/threshold and hysteresis detection); the design is informed by the bio-signal deconvolution and event-graph literature rather than porting any single paper verbatim.

Synthesis Engines LIVE

All synthesis is Accelerate/vDSP-vectorized and audio-thread-safe (pre-allocated buffers, no allocation in the render path). Each engine exposes the same bio-reactive mapping surface.

EchoelDDSP
Harmonic-plus-noise — 64 partials (vvsinf/vDSP_dotpr) + 65-band FIR noise. 5 noise colors (white/pink/brown/blue/violet), 8 spectral shapes (natural, bright, dark, formant, metallic, hollow, bell, flat), ADSR (linear/exp/log), timbre transfer (violin, flute, trumpet, cello, clarinet, oboe), convolution reverb.
EchoelCellular
Cellular-automata synthesis — 8 rules (30, 90, 110, 150, 184, 60, 105, 73), 4 modes (wavetable, additive, FM, spectral-2D / Game of Life), 5 seed patterns.
EchoelModalBank
Physical modal resonator — 8 materials (bell, plate, bar, string, glass, drum, gong, custom); stiffness (inharmonicity), damping, size, brightness, strike position/velocity; impulse or continuous (bowed/breath) excitation.
Toolkit
EchoelVDSPKit (DFT, real FFT with 5 windows, FIR convolution, biquad cascade / parametric EQ, decimator, spectral analyzer), EchoelSVFilter (Chamberlin LP/HP/BP/notch), EchoelLFO (5 waveforms, 0.01–20 Hz), EchoelEntrainment (isochronic Delta 2 / Theta 6 / Alpha 10 / Beta 20 / Gamma 40 Hz).
Bio-mappings (7)
Heart rate → filter-LFO speed + vibrato; coherence → filter cutoff + harmonicity; HRV → reverb mix/decay + damping; breath depth → filter-LFO depth; breath phase → amplitude envelope; coherence trend → spectral-shape morph. Applied via synth.applyBioReactive(…).

Effects & Mastering

Reverb LIVE
Convolution reverb with synthetic impulse response inside EchoelDDSP — wet/dry and decay control, HRV-reactive.
EQ + auto-gain LIVE
AutoMixChain — 4-band EQ (40 Hz high-pass, 180 Hz low-shelf, 3 kHz parametric, 10 kHz high-shelf) + LUFS auto-gain to −14 LUFS (±12 dB), with 4 presets (balanced, warm, bright, transparent).
Filter + saturation LIVE
LFO-swept state-variable filter; soft tanh saturation in the voice-mix stage.
More ROADMAP
Delay, chorus/flanger/phaser/tremolo, and dedicated compressor/limiter with analog (VCA/Opto/FET/VariMu/Tube) emulations.

Audio Foundation LIVE

AudioEngine
Master AVAudioEngine with a stereo mixer bus at 48 kHz. Hosts the synth source node, bio-reactive voices and the mix/export chain. A single .start() after all voices are attached avoids a hot-attach crash.
AudioConfiguration
48 kHz preferred; buffer presets 128 / 256 / 512 frames (2.67 / 5.3 / 10.7 ms); playAndRecord session with Bluetooth; real-time thread priority.
Capture & export
MicrophoneManager (1024-pt FFT), RetroCapture (30 s stereo 48 kHz pre-roll ring buffer → .caf), SingleExport (LUFS-normalized WAV/AAC). MultiTrackRecorder is a skeleton. ROADMAP

Generative Composition LIVE

Your biometrics compose harmonic, melodic and rhythmic loops in any key and BPM — with an optional beat layer blending samples and physical-model drum synthesis — which you render to .wav and MIDI for your DAW.

BioComposer
Bio-driven harmonic/melodic loop generation, 30–300 BPM, 16th-note clock (step = (60/BPM)/4 s) for key/tempo locking. Per-note velocity, automation and richer voice-leading are ROADMAP.
Voice triggering
Notes are fired lock-free via an atomic trigger counter (no allocation on the audio thread) into the bio-reactive synth voices. A drum/sampler track and a step sequencer are ROADMAP, not in the app today.

Standalone instrument NOT A PLUGIN

Echoelmusic is a standalone iPhone instrument. It is not an Audio Unit (AUv3) plugin, and it does not host third-party AUv3 plugins. Both were built and then deliberately removed: an instrument you play with your body is not a workstation, and a plugin surface is a second product with its own host-compatibility matrix. Neither is on the roadmap.

Into a DAW
Over the open interfaces instead: a virtual CoreMIDI source (MIDI 2.0 / MPE) any DAW records live, plus WAV and MIDI file export. See Formats & I/O.

Visuals & Video LIVE / ROADMAP

Studio UI & App Wiring LIVE

EchoelmusicApp (@main) builds the graph in order — MicrophoneManager → AudioEngine → EchoelStore → BeatPlayer → EngineBus, then the bio publishers (HealthKit, Polar H10), the BioReactiveSynthVoice, the BioEventPublisher, MIDI (CoreMIDI), and the OSC sender — configures audio before the UI, then mounts the studio. SwiftUI observes EngineBus snapshots; nothing in the view layer touches the audio thread.

BioStripView
Always-on readout: HR · HRV · Br · Coh, applied synth-frame count, and activity dots (bio events, MIDI, OSC), plus a play/stop toggle and the active source tag.
Studio views
Perform (scene grid), Mix (voice + AutoMix + signal status), Export (WAV/AAC + MIDI), Settings (bio source), and a 60-second camera-pulse measurement. Short-form video export is ROADMAP.

EchoelSync — OSC API LIVE

OSCSender mirrors the bio frame out over UDP (Network.framework), so any visual or audio tool on the network can react to the body. OSC 1.0, big-endian 32-bit floats, ~100 ms cadence (sent only when the frame changes). Default target localhost:8000; target latency <5 ms on LAN. Works with Resolume, TouchDesigner, MadMapper, Sonic Pi and TidalCycles. Ableton Link sync is ROADMAP.

An opt-in ADMOSCSender additionally streams the body as an audio object over ADM-OSC (the open Audio-Definition-Model-over-OSC standard): breath → azimuth, coherence → distance, HRV → elevation, motion → gain on /adm/obj/{n}/…. This makes Echoel a bio-reactive object source for object-based renderers (Adamson FletcherMachine, L-ISA, d&b Soundscape) — open standard, no vendor SDK. Configured from the Sync tab; off by default. NEW

Concurrency & Audio-Thread Safety

The split is strict. The control plane (@MainActor @Observable) drives SwiftUI; the data plane (lock-free SPSC queues) drives audio. A producer never blocks a consumer.

Forbidden on the audio thread

  • malloc / free, array growth
  • locks, mutexes, semaphores
  • ObjC messaging, GCD / async
  • file or network I/O, logging

Allowed

  • pre-allocated Float buffers
  • vDSP / Accelerate, C math
  • ring-buffer read/write
  • atomic-width property reads
